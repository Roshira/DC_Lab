Цей експеримент чітко показує, що вибір алгоритму є найважливішим: послідовний std::sort ($O(n \log n)$) виявився набагато швидшим за будь-яку версію "бульбашки" ($O(n^2)$). Хоча паралельна "бульбашка" (алгоритм парно-непарного транспонування) дійсно прискорює свою повільну послідовну версію, вона все одно не може зрівнятися з оптимізованим std::sort. Приріст від паралелізму також має свою ціну, оскільки обмін даними між процесами (MPI) створює додаткові накладні витрати. Крім того, запуск більшої кількості процесів, ніж є фізичних ядер (з --oversubscribe), лише погіршує ситуацію, змушуючи систему витрачати час на перемикання завдань. Таким чином, для справжньої ефективності потрібен не тільки паралелізм, але й розумний базовий алгоритм.
